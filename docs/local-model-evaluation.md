# In-app local-model quality assessment (experimental)

The Character Studio **Fidelity Lab** now includes **Run local model assessment**. This is a deliberately small, repeatable diagnostic against **your currently loaded chat model**, rather than a simulation of model responses or a score invented by the app.

## What runs

A synthetic character **Mara Vale** lives in **Port Arlen**, a contemporary nonmagical coastal world. The fixture has established age, values, family, job, routine-relevant references, voice and motivation. The test never changes the user's characters, scenes, world atlas, memory, or local-model settings.

The app submits **seven** fixed tasks sequentially via the same local `/api/chat` path used by regular generation:

1. **Phone style** (single-field prompt): check format and obvious visual-only gesture contamination in an audio-only context.
2. **Daily routine** (single-field prompt): check format and claims that turn habitual schedules into real-time locations.
3. **Behavior under stress** (single-field prompt): check format, concise expression, and obvious conflicts with the world.
4. **World entity proposals**: use the Character → World bridge to extract named people/places from a source-grounded biography; recheck source quotations and compare against a small hand-authored expected-name set.
5. **Everyday texting**: check response and channel formatting.
6. **Boundary-setting**: check the NPC retains agency rather than taking voluntary player actions.
7. **Phone call**: check for visual-only cues and player agency errors.

For each task the app records the **actual time spent waiting for its local-model response**, whether the proposed field/world JSON was parseable and allowed, and warnings generated by explicit heuristics. The resulting report is visible in Fidelity Lab, can be exported as JSON, and remains **transient**: it is not saved into story history or world canon.

After those tasks, the app optionally runs two synthetic embedding questions through its configured **loopback embedding model**:

- *Implicit positive*: “I worry the rain might ruin my jewelry” should potentially retrieve an older silver pendant memory.
- *Unrelated negative*: a cooking question should not retrieve unrelated character memories.

The report includes whether the source was retrieved, number of matches returned for the unrelated query, and individual embedding-query latencies. When `RP_EMBEDDING_MODEL` is not configured or unavailable, it reports **disabled/unavailable** rather than fabricating a semantic recall score.

## Interpreting results

These are **development diagnostics**, not validated human-likeness, emotional realism, literary quality, or a statistically meaningful false-positive rate. Heuristic checks detect a small set of common failures but do not catch nuanced contradictions, circular voice, or every false assertion. A parse-valid field can still be a poor character portrayal. The six-test memory suite and source-authorization tests remain the more important deterministic safety and privacy gates.

A real-model evaluation requires actually loading and running your local chat and embedding models. GitHub CI only tests the assessment plumbing using deterministic stubs. This chat cannot reach your computer's localhost, so no actual performance numbers or quality claims about your GPU are asserted here.

## How to use

Open the app, load your preferred chat model in **Setup**, open any character in **Character Studio**, select the **Fidelity Lab** tab, and choose **Run local model assessment**. The assessment uses a fixed synthetic profile for comparison, not the currently open character's private story. Wait for all seven model requests to finish in the app; you can cancel or close the dialog to stop. When finished, review warnings and export the JSON.

For optional embedding checks, configure a supported local embedding model as described in [Semantic Recall v1](semantic-recall-v1.md). No extra dependency or cloud model is needed. To compare different models, run the same assessment once per model and compare the JSON latency, field format, source-backed extraction, and warnings.

Future improvements should introduce larger human-reviewed scenario sets, scorer calibration and actual end-to-end conversational replay; do not treat heuristic warning counts as objective personality scores.
